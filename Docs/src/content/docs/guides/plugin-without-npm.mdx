---
title: 'Using the Plugin Without npm'
description: Vendor the Vite.NET plugin directly into your project instead of installing it from npm.
---

import { Steps, Aside, Tabs, TabItem } from '@astrojs/starlight/components';

If you would rather not depend on the `vite-dotnet` package from npm — for example, in an air-gapped
environment, a monorepo that vendors its tooling, or a project that pins all dependencies by hand —
you can drop the plugin straight into your SPA and import it locally. It behaves identically to the
published package.

<Aside type="note">
This is entirely optional. For most projects, `npm install vite-dotnet` (see
[Installation](/introduction/installation)) is simpler and keeps you on the latest version.
</Aside>

## Vendor the plugin file

<Steps>

1. **Create the plugin file** in your SPA folder, next to `vite.config.ts`. Name it
   `vite-dotnet.ts` (or `vite-dotnet.js` if your config is plain JavaScript) and paste in the
   plugin source:

   <Tabs>
     <TabItem label="TypeScript">
       ```ts title="ReactApp/vite-dotnet.ts"
       import { writeFileSync, mkdirSync } from 'fs'
       import { basename, join, posix, resolve } from 'path'
       import { version as viteVersion } from 'vite'

       export type PluginConfig = {
         entrypoint: string
         containerElementId: string
       }

       // Derive the SPA's folder name (e.g. "ReactApp") from the current working directory.
       function retrieveAppFolder(): string {
         const currentDir = process.cwd().split(/[\\/]/).pop()
         return currentDir!
       }

       function outputOptions(assetsDir: string) {
         const outputFileName = (ext: string) => ({ name }: { name: string | undefined }) => {
           const shortName = basename(name!).split('.')[0]
           return posix.join(assetsDir, `${shortName}.[hash].${ext}`)
         }

         return {
           entryFileNames: outputFileName('js'),
           chunkFileNames: outputFileName('js'),
           assetFileNames: outputFileName('[ext]'),
         }
       }

       // Force plain-`ws` HMR and emit the correct option key for the running Vite version
       // (server.ws.* on Vite 8+, server.hmr.* on older versions).
       function websocketServerOptions() {
         const major = parseInt((viteVersion ?? '').split('.')[0], 10)
         const options = { protocol: 'ws' as const }
         return major >= 8 ? { ws: options } : { hmr: options }
       }

       const REACT_PLUGIN_NAMES = ['vite:react-babel', 'vite:react-refresh', 'vite:react-swc']

       function isReactApp(plugins: readonly { name: string }[]): boolean {
         return plugins.some((plugin) => REACT_PLUGIN_NAMES.includes(plugin.name))
       }

       export default function ViteDotNetPlugin(entrypoint: string, containerElementId: string) {
         return ViteDotNet({ entrypoint, containerElementId })
       }

       function ViteDotNet(plugConfig: PluginConfig) {
         let isReact = false

         return {
           name: 'ViteDotNet',
           enforce: 'post' as const,
           configResolved(config: any) {
             isReact = isReactApp(config.plugins)
           },
           config: () => {
             const currentDir = retrieveAppFolder()

             return {
               server: {
                 ...websocketServerOptions(),
               },
               build: {
                 outDir: `../wwwroot`,
                 emptyOutDir: true,
                 manifest: `${currentDir}/manifest.json`,
                 rollupOptions: {
                   input: plugConfig.entrypoint,
                   output: outputOptions(currentDir),
                 },
               },
             }
           },
           configureServer(server: any) {
             const generateDevManifest = () => {
               const { config } = server
               const port = config.server.port || 5173
               const currentDir = retrieveAppFolder()

               const devManifest = {
                 port,
                 entrypoint: plugConfig.entrypoint,
                 containerElementId: plugConfig.containerElementId,
                 isReact,
               }

               const outputDir = resolve(process.cwd(), '..', 'wwwroot', currentDir)
               mkdirSync(outputDir, { recursive: true })

               writeFileSync(
                 join(outputDir, 'manifest.dev.json'),
                 JSON.stringify(devManifest, null, 2),
               )
             }

             server.httpServer?.once('listening', generateDevManifest)
           },
           generateBundle(this: any) {
             const currentDir = retrieveAppFolder()

             const prodManifest = {
               entrypoint: plugConfig.entrypoint,
               containerElementId: plugConfig.containerElementId,
               isReact,
             }

             this.emitFile({
               type: 'asset',
               fileName: `${currentDir}/manifest.prod.json`,
               source: JSON.stringify(prodManifest, null, 2),
             })
           },
         }
       }
       ```
     </TabItem>

2. **Import it locally** in `vite.config.ts` using a relative path instead of the package name:

   ```ts title="ReactApp/vite.config.ts" ins={3} del={2}
   import { defineConfig } from 'vite'
   import ViteDotNetPlugin from 'vite-dotnet'
   import ViteDotNetPlugin from './vite-dotnet'
   import react from '@vitejs/plugin-react'

   export default defineConfig({
     plugins: [
       react(),
       ViteDotNetPlugin('src/main.tsx', 'root'),
     ],
   })
   ```

3. **Use it exactly as before.** The arguments, the plugin order (after your framework plugin), and
   the manifests it emits are all identical to the npm package. Continue with
   [Backend Configuration](/guides/backend-configuration) and [Rendering a SPA](/guides/rendering-a-spa).

</Steps>

<Aside type="tip" title="You need Node types for TypeScript">
The plugin uses Node's `fs` and `path` modules. If your SPA doesn't already have them typed, install
the Node types as a dev dependency so the vendored `.ts` file type-checks:

```bash
npm install -D @types/node
```
</Aside>

## Alternatives to vendoring

If you want to avoid the npm **registry** but still use a package, these both work without copying
source:

- **Local path** — reference the plugin folder directly. Useful in a monorepo:

  ```bash
  npm install ../path/to/vite-dotnet
  ```

- **Tarball** — pack the plugin once (`npm pack`) and commit or share the resulting `.tgz`, then:

  ```bash
  npm install ./vite-dotnet-1.0.0.tgz
  ```

<Aside type="caution">
Whichever approach you choose, you take on manual updates: when a new version of Vite.NET ships,
you'll need to re-copy the file (or re-install the path/tarball) to pick up changes. The npm package
is the only option that updates with `npm update`.
</Aside>
