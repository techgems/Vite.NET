Vite.NET has two halves: a NuGet package for your ASP.NET Core app, and a Vite plugin for your
SPA. This page installs both. If you are starting from scratch, the [Quick Start](/introduction/quick-start)
walks through the whole project layout.

<Aside type="note">
This guide assumes you already have an ASP.NET Core project (Razor Pages or MVC) and a Vite SPA
folder inside it (for example `ReactApp/`, created with `npm create vite@latest`).
</Aside>

## 1. Install the NuGet package

<Steps>

1. **Add the package to your ASP.NET Core project**

   The current release is **{nugetVersion}**. Because it is a prerelease, pass the version
   explicitly (or `--prerelease`) so NuGet does not skip it:

   <Code lang="bash" code={`dotnet add package TechGems.ViteDotNet --version ${nugetVersion}`} />

   Or, editing the `.csproj` directly:

   <Code lang="xml" code={`<PackageReference Include="TechGems.ViteDotNet" Version="${nugetVersion}" />`} />

2. **Register the integration in `Program.cs`**

   ```csharp
   using ViteDotNet;

   var builder = WebApplication.CreateBuilder(args);

   builder.Services.AddRazorPages();
   builder.Services.AddViteIntegration(builder.Configuration);
   ```

3. **Register the tag helpers in `_ViewImports.cshtml`**

   ```razor
   @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
   @addTagHelper *, ViteDotNet
   ```

</Steps>

## 2. Install the Vite plugin

<Steps>

1. **Add the plugin to your SPA folder**

   From inside your SPA directory (e.g. `ReactApp/`). The plugin has its own release track, so
   install **{npmVersion}** here — as a prerelease it is not picked up by a plain
   `npm install vite-dotnet`:

   <Code lang="bash" code={`npm install vite-dotnet@${npmVersion}`} />

2. **Register it in `vite.config.ts`**

   Add the plugin **after** your framework plugin, passing your entrypoint and the id of the
   element the SPA mounts into:

   <Tabs>
     <TabItem label="React">
       ```ts
       import { defineConfig } from 'vite'
       import react from '@vitejs/plugin-react'
       import ViteDotNetPlugin from 'vite-dotnet'

       export default defineConfig({
         plugins: [
           react(),
           ViteDotNetPlugin('src/main.tsx', 'root'),
         ],
       })
       ```
     </TabItem>
     <TabItem label="Svelte">
       ```ts
       import { defineConfig } from 'vite'
       import { svelte } from '@sveltejs/vite-plugin-svelte'
       import ViteDotNetPlugin from 'vite-dotnet'

       export default defineConfig({
         plugins: [
           svelte(),
           ViteDotNetPlugin('src/main.ts', 'app'),
         ],
       })
       ```
     </TabItem>
     <TabItem label="Vue">
       ```ts
       import { defineConfig } from 'vite'
       import vue from '@vitejs/plugin-vue'
       import ViteDotNetPlugin from 'vite-dotnet'

       export default defineConfig({
         plugins: [
           vue(),
           ViteDotNetPlugin('src/main.ts', 'app'),
         ],
       })
       ```
     </TabItem>
   </Tabs>

</Steps>

<Aside type="caution" title="Plugin order matters">
The Vite.NET plugin uses `enforce: 'post'`, so it must be registered **after** your framework
plugin. That is how it detects a React app (which needs an extra HMR preamble in development).
See [The Vite Plugin](/guides/the-vite-plugin) for details.
</Aside>

## 3. Point the back end at your app folder

Add the SPA's **directory name** to your configuration under the `ViteDotNet` section. This is
the only backend configuration required.

```json title="appsettings.Development.json"
{
  "ViteDotNet": "ReactApp"
}
```

That's it — everything else (entrypoint, container element id, dev-server port, whether the app
is React) is generated by the plugin at dev-server start and build time. Continue to the
[Quick Start](/introduction/quick-start) to render your SPA into a page.
