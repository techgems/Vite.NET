# Setup

Installing Vite.NET into an ASP.NET Core project (Razor Pages or MVC) that contains a Vite SPA
folder, and rendering the SPA for the first time.

## Target layout

The SPA folder lives inside the ASP.NET Core project. Vite's build writes into the project's
`wwwroot`, so compiled assets are served as normal static files.

```
YourApp/
├── Program.cs
├── appsettings.Development.json
├── Pages/
│   ├── Index.cshtml          the page hosting the SPA
│   └── _ViewImports.cshtml
├── ReactApp/                 the Vite SPA (npm create vite@latest)
│   ├── vite.config.ts
│   ├── package.json
│   └── src/main.tsx          the entrypoint
└── wwwroot/                  Vite build output lands here
    └── ReactApp/
```

## 1. NuGet package

The current release is `1.0.0-beta`. Because it is a prerelease, pass the version explicitly
(or `--prerelease`) so NuGet does not skip it:

```bash
dotnet add package TechGems.ViteDotNet --version 1.0.0-beta
```

Or in the `.csproj`:

```xml
<PackageReference Include="TechGems.ViteDotNet" Version="1.0.0-beta" />
```

Register the integration in `Program.cs`:

```csharp
using ViteDotNet;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRazorPages();
builder.Services.AddViteIntegration(builder.Configuration);
```

Register the tag helpers in `_ViewImports.cshtml` — the `Pages` folder for Razor Pages, `Views`
for MVC:

```razor
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
@addTagHelper *, ViteDotNet
```

## 2. Vite plugin

From inside the SPA directory. The plugin tracks the NuGet package version, so it is a
prerelease here too and needs the explicit version:

```bash
npm install vite-dotnet@1.0.0-beta
```

Register it **after** the framework plugin, passing the entrypoint and the id of the element the
SPA mounts into. The plugin uses `enforce: 'post'` and inspects the resolved plugin list to
detect React (which needs an extra HMR preamble in development) — registering it first breaks
that detection.

### React

```ts title="ReactApp/vite.config.ts"
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import ViteDotNetPlugin from 'vite-dotnet'

export default defineConfig({
  plugins: [
    react(),
    ViteDotNetPlugin('src/main.tsx', 'root'),
  ],
})
```

### Svelte

```ts title="SvelteApp/vite.config.ts"
import { defineConfig } from 'vite'
import { svelte } from '@sveltejs/vite-plugin-svelte'
import ViteDotNetPlugin from 'vite-dotnet'

export default defineConfig({
  plugins: [
    svelte(),
    ViteDotNetPlugin('src/main.ts', 'app'),
  ],
})
```

### Vue

```ts title="VueApp/vite.config.ts"
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ViteDotNetPlugin from 'vite-dotnet'

export default defineConfig({
  plugins: [
    vue(),
    ViteDotNetPlugin('src/main.ts', 'app'),
  ],
})
```

## 3. Point the back end at the app folder

Add the SPA's directory name under the `ViteDotNet` key. This is the only backend configuration
required:

```json title="appsettings.Development.json"
{
  "ViteDotNet": "ReactApp"
}
```

Everything else — entrypoint, container element id, dev-server port, whether the app is React —
is generated by the plugin at dev-server start and build time.

## 4. Render the SPA

```razor title="Pages/Index.cshtml"
@page
@model YourApp.Pages.IndexModel
@{
    Layout = null;
}

<dev-vite-scripts app-name="ReactApp" />
```

With a single configured app, `<dev-vite-scripts />` without `app-name` resolves to it.

## 5. Run it

```bash
# terminal 1 — writes wwwroot/ReactApp/manifest.dev.json once the server binds its port
cd ReactApp
npm run dev
```

```bash
# terminal 2
dotnet run
```

Opening the page before the dev server is listening renders a "Vite Dev Server Not Found"
message that retries — start the dev server and refresh. `RunViteDevServer()` removes the need
for the second terminal (see `workflows.md`).

## 6. Production

```bash
cd ReactApp
npm run build
```

```razor title="Pages/Index.cshtml"
<prod-vite-scripts app-name="ReactApp" />
```

The build writes the hashed bundle, Vite's `manifest.json`, and the plugin's
`manifest.prod.json` into `wwwroot/ReactApp/`; the production helper reads both and emits the
final `<link>` / `<script>` tags. No dev server involved.
